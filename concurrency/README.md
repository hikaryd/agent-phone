# Необязательная очередь одного браузера

Код подходит только клиентам, которые вызывают совместимый `browser-use` CLI с Python input. Его нужно настроить отдельно от телефона и проверить на конкретной версии клиента. Он не изолирует cookies или профиль и не защищает от прямых CDP-клиентов.

Четыре атомарных чтения используют разные именованные сессии; пятое ждёт. Формат Python input для чтения: первая строка `# phone:read-v1`, следующая строка — JSON `{"url":"https://example.org/","max_chars":20000}`. Чтение получает URL, заголовок и текст через ограниченный CDP; собственный JavaScript, ввод и скриншоты в этом режиме недоступны. Каждая задача создаёт фоновую вкладку и закрывает её по завершении. Другой Python работает эксклюзивно; именованная интерактивная сессия удерживает свою вкладку. Завершение — отдельный вызов `# phone:finish-v1` с той же сессией.

Скопируйте `runtime.py` и `shim.py` в приватный каталог сервера. Конфигурация `~/.config/phone-browser/scheduler.json` (`0600`) содержит абсолютные `upstream_argv`, `read_python`, `runtime_file`, `preamble_file`, `state_dir`, `phone_cdp_urls`, а также `wait_seconds` и `preexisting_sessions`. `PHONE_SCHEDULER_CONFIG` меняет путь конфигурации. Исходный `browser-use` должен быть точно установленным бинарником, не рекурсивным shim. Если клиент использует префикс собственного API для именных сессий, сохраните его точный текст в `preamble_file`; несовпадение закрывает доступ. `read_python` должен иметь совместимый пакет `websockets`.

Перед заменой CLI сохраните прежний файл и список живых сессий. Проверьте четыре пересекающихся чтения, ожидание пятого, эксклюзивный ввод, прерывание владельцем, сетевое восстановление и очистку только собственных вкладок. При откате верните прежний CLI атомарно, сохранив `state_dir` и lock-файлы. Не повторяйте прерванные внешние действия без проверки результата.
